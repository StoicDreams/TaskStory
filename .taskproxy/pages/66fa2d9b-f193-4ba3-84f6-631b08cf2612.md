# Run Tests

<webui-page-segment>

Tests run in two tiers, and need no build or running server, since they serve the site directly from `webapp/`. Only the framework loads from the CDN. Analytics and other outside requests are blocked, and `api.myfi.ws` returns an empty response. Both tiers test the minified files the site loads, one test at a time.

- **Unit tests** ([Vitest](https://vitest.dev), `tests/unit`) check the site's files, and run its pages and components in a simulated browser. Most tests belong here.
- **Browser tests** ([Playwright](https://playwright.dev), `tests/browser`) open every page in a real browser, and test what needs one, such as layout, the mouse, and media.

```pwsh
npm install
npx playwright install chromium
```

On Linux the browser tests use `/usr/bin/chromium` if it exists, so the second command can be skipped. Set `PW_CHROMIUM_PATH` to use a different browser.

## Commands

Run the unit tests, then the browser tests, against the live CDN, which is what the deployed site uses

```pwsh
npm test
```

Run only the unit tests. A test that passed before is skipped while nothing it depends on has changed (results are kept in `.test-cache/unit`, which is committed)

```pwsh
npm run test:unit
```

Run only the browser tests

```pwsh
npm run test:browser
```

Run every test, ignoring the unit test cache

```pwsh
npm run test:full
```

Run everything against the `MyFiCDN` checkout next to this repo. Use this to try framework changes before pushing them

```pwsh
npm run test:local-cdn
```

Open the interactive runner for the browser tests, with watch mode and a timeline for each test

```pwsh
npm run test:ui
```

Open the last browser test report, with a screenshot and trace for each failure

```pwsh
npm run test:report
```

Run one unit test file, or unit tests by name

```pwsh
npx vitest run tests/unit/site.test.mjs
npx vitest run -t "nav.json"
```

Run browser tests by name

```pwsh
npx playwright test -g "loads" --project=live-cdn
```

Run the Rust tests

```pwsh
cargo test
```

## Stress tests

Once a week, for each project worked on that week, run the browser tests the week's changes affect many times each under heavy load. A test that fails here only some of the time is a timing race to fix. This never runs as part of a normal test run, Publish, or CI. With nothing changed in the last 7 days it says so and runs nothing.

```pwsh
pwsh ./PowerShell/StressTests.ps1
```

Stress every test, whatever changed

```pwsh
pwsh ./PowerShell/StressTests.ps1 -All
```

Look back further, or run each test more or fewer times

```pwsh
pwsh ./PowerShell/StressTests.ps1 -Days 14 -Repeat 5
```

## Test files:

- `tests/unit/site.test.mjs` checks the config and SEO files, links between pages, prerendered pages, the theme's contrast, min files, and that every component has tests. `tests/browser/site.spec.mjs` opens every linked page and checks it loads with a title, no errors, and all of its components. Both are the same in every site, so change them in every site at once.
- `tests/unit/support/site.mjs` (unit tests) and `tests/support/site.mjs` (browser tests) provide `test`, `expect`, and `openPage(page, route)`, and serve the site from `webapp/`. They and the other files in those folders are the same in every site.
- `tests/site.config.mjs` holds this site's settings.
- Test this site's own pages and components in `tests/unit/{name}.test.mjs`, and only what needs a real browser in `tests/browser/{name}.spec.mjs`.

Any uncaught error during a test fails that test, even if its checks pass. A test this site fails is a bug to fix, never one to mark as expected to fail.
